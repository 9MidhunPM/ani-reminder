# Local development

[Back to the README](../README.md)

This guide runs the Next.js application on your computer and PostgreSQL in Docker. It does not deploy the production image or start a recurring scheduler.

## Prerequisites

- Git, Node.js 22 or later, and npm 10 or later. Node.js 22 matches [CI](../.github/workflows/verify.yml) and the [Dockerfile](../Dockerfile).
- Docker Engine or Docker Desktop with Compose v2, including `docker compose up --wait`.
- A POSIX shell for the examples and OpenSSL for secret generation.
- Free local ports 3000 and 5432, or deliberately chosen replacements.

Start in the repository root. Use `npm ci` to install the committed dependency versions. When changing dependencies intentionally, update and review `package-lock.json` separately.

## Configure the application

```sh
npm ci
test -e .env || cp .env.example .env
```

Edit `.env` locally. Generate each of the three secrets separately with `openssl rand -base64 32`; paste the results into their matching fields. Never put real values in documentation, screenshots, issues, or commits.

| Variable | Local purpose |
| --- | --- |
| `DATABASE_URL` | Prisma's PostgreSQL connection. The example matches the Compose database, user, password, and host port. |
| `AUTH_URL` | Application origin, normally `http://localhost:3000`. Used for authentication and same-origin checks. |
| `AUTH_SECRET` | Auth.js session protection and keyed rate-limit identifiers. |
| `CRON_SECRET` | Bearer token for `/api/cron`, separate from authentication. |
| `DATA_ENCRYPTION_KEY` | Base64 encoding of exactly 32 bytes for AES-256-GCM encryption of ntfy topics. |

Keep the encryption key with the database it protects. Generating a replacement does not re-encrypt stored topics, and an incorrect key prevents decrypting them. Use fresh local secrets instead of copying production secrets or a production database.

Next.js loads `.env` during development/build/start. Standalone Node scripts should receive their environment explicitly, for example:

```sh
node --env-file=.env --import tsx scripts/scheduler.ts status
```

This is the same CLI as `npm run scheduler -- status`, with Node explicitly loading `.env` first. Exported variables take precedence over Node's env-file values. Keep local configuration in `.env` for this walkthrough; an additional `.env.local` can make Next.js use different values from standalone tools.

## Start and verify

```sh
docker compose up -d --wait postgres
npx prisma generate
npm run db:deploy
npm run dev
```

`db:deploy` applies committed migrations to the database selected by `DATABASE_URL`. `db:migrate` is for developing a new schema migration, not routine setup. Prisma client generation is a separate step and should be repeated after pulling schema changes.

The checked-in Compose file runs only PostgreSQL 16. It publishes `5432:5432` using known development credentials, so do not use it on a public or shared host. A production database belongs on a private network. If port 5432 is already occupied, change the local host mapping and `DATABASE_URL` together; changing only the URL does not change Docker's port mapping.

Open `http://localhost:3000`. In another terminal:

```sh
curl --fail http://localhost:3000/api/health
```

A successful check returns `{"status":"ok"}` after `SELECT 1` succeeds. It does not prove that migrations, AniList, notification delivery, or phone subscriptions are working.

Create a local account with a password of at least 12 characters and no more than 72 UTF-8 bytes. The ntfy topic must contain 12–64 letters, numbers, underscores, or dashes. Use a long random development-only topic, such as one generated by the signup form, and subscribe to it separately in ntfy if you intend to test delivery. A hard-to-guess topic name is not a replacement for access controls.

Search and follow actions contact AniList. The development server does not start the container's minute-level cron. Episode delivery starts disabled after migration; leave it disabled for ordinary development and synthetic fixtures. The explicit **test notification** action is independent of this switch and can send a real message to `ntfy.sh`.

## Stop and resume without discarding data

Stop Next.js with Ctrl+C, then stop PostgreSQL:

```sh
docker compose stop postgres
```

Resume with `docker compose up -d --wait postgres` and `npm run dev`. The named `ani-reminder-postgres` volume retains local accounts and reminders. Do not use `docker compose down --volumes` unless you intend to discard that database.

## Common setup problems

| Symptom | Check |
| --- | --- |
| Database connection error or `/api/health` returns 503 | Confirm Docker is running, `docker compose ps` reports PostgreSQL healthy, and `DATABASE_URL` matches its host port and credentials. |
| Missing tables or scheduler control record | Run `npm run db:deploy` against the intended local database. Health checks alone do not validate the schema. |
| Prisma client or generated type errors | Run `npx prisma generate`, then rerun the check. |
| Signup or settings changes reject the origin | Open the exact origin in `AUTH_URL`; `localhost` and `127.0.0.1` are different origins. Restart Next.js after changing environment values. |
| Topic encryption fails | Check that `DATA_ENCRYPTION_KEY` decodes to 32 bytes and is the original key for any existing records. Do not print it in a bug report. |
| No episode notifications | Check [scheduler behavior](scheduler.md). Local `dev`/`start` commands do not start cron, and an enabled account preference does not enable global delivery. |
| Browser tests cannot connect | Build first and opt into Playwright's server with `E2E_START_SERVER=true`, or start a QA server yourself. See the testing guide. |

For application checks, see the README's command list. For the production image, upgrades, and recovery, use the [release runbook](deployment.md).
